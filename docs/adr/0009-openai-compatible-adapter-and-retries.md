# ADR 0009: OpenAI-compatible adapter and runner retries

Status: accepted. Date: 2026-10-04. Completes the deferred parts of [ADR 0002](0002-provider-contract.md) (the `auth_error` and `connection_error` kinds, and retries owned by the runner).

Covers M3a: an HTTP adapter for servers that implement `POST {base_url}/chat/completions`, and bounded runner-level retries with a recorded attempt history. All tests use a local fake HTTP server on loopback. No real provider, endpoint or credential is used anywhere in the repository, and the adapter has not been run against any real service.

## Decisions
1. **One attempt in the adapter; retries in the runner.** `Provider.generate` still makes a single HTTP request and never retries (ADR 0002 decision 2). `run_one` owns retries through `RetryPolicy`. The adapter has no hidden retry loop and does not sleep.
2. **`RetryPolicy`.** The core default is one attempt (`NO_RETRY`), so nothing changes unless a caller opts in. HTTP runs opt in explicitly with `HTTP_RETRY_POLICY` (three attempts), passed as `execute_run(retry=...)`; nothing enables it automatically. Only `timeout`, `rate_limit`, `server_error` and `connection_error` are retried. `auth_error`, `invalid_request`, `malformed_response`, `unsupported_capability` and `internal_error` never are. The wait before retry *n* is `min(1 s * 2^(n-1), 30 s)`, with no jitter, so it is deterministic. If a failure carries `provider_metadata["retry_after_s"]` the wait is at least that long, up to 60 s; a larger request stops retrying and the failure is recorded rather than sleeping that long. Tests inject the sleep function, so they never sleep.
3. **Attempt history.** `ExecutionRecord.attempts` is `None` when retries are not enabled, and is then omitted from the serialized record, so result lines for runs without retries are byte-identical to those written before. With a policy of several attempts it lists every call (`result`, its own `elapsed_s`, and the `waited_s` requested before it). `result` and `elapsed_s` stay those of the final call, so scoring and comparison read the same fields as before. The last attempt equals the final result and every earlier attempt is a failure (validated). Old result lines load unchanged; lines that contain `attempts` or the new kinds cannot be read by older code.
4. **Resume.** A recorded failure counts as done and is never retried on resume. The in-flight duplicate-call limit of ADR 0003 is unchanged. The policy is not recorded in the manifest, so a resume with a different policy is not detected; each retried result records its own attempts instead.
5. **New failure kinds** `auth_error` (HTTP 401 and 403) and `connection_error` (refused, reset, no usable response). They are appended to the enum, and `connection_error` is retryable.
6. **Timeouts.** A client timeout is a `timeout` failure. Retrying it can repeat a request that the server already processed, and may be billed twice. Set `max_attempts=1` if that matters. Timeouts are per operation (connect, read), not a total wall-clock limit.
7. **Profile and configuration.** `OpenAICompatibleProfile` is a strict, frozen model: `name` (the provider name recorded in manifests and results), `base_url`, `api_key_env` (the *name* of an environment variable, never a key), timeouts, `supported_params`, `max_stop_sequences`, `max_tokens_field` and `max_response_bytes`. There is no registry, no YAML loader and no CLI yet; profiles are built in Python. The base URL must be http or https, with no credentials, query or fragment (validation errors never echo it). A key is never configured for plain http to a non-loopback host. If the named variable is unset, empty or has surrounding whitespace or control characters, construction raises `ProviderConfigError` naming only the variable.
8. **Parameters.** The model is `request.model`; nothing is hardcoded. A parameter the profile does not declare as supported, or more `stop` sequences than allowed, returns `unsupported_capability` before any HTTP request, naming the parameters but not their values. The default supported set is `temperature`, `top_p`, `max_tokens`, `stop` and `response_format`. `seed` is off by default because servers often do not honour it; a profile can opt in, but sending a parameter does not mean the server honoured it. The max-tokens field name is a profile setting (`max_tokens` or `max_completion_tokens`).
9. **Responses fail closed.** Exactly one choice with string content is required; `finish_reason` is stored raw; `returned_model` is kept when the server gives a non-blank string. `usage` is `None` when absent or empty, partial counts stay `None` where missing, and any invalid count (negative, boolean, non-integer) is `malformed_response`. Nothing is repaired and no usage or cost is ever invented. Invalid JSON, a non-object body, NaN, no or several choices, non-string content and an oversized body (default limit 4 MiB) are all `malformed_response`.
10. **Messages and secrets.** Failure messages are fixed text, the status code and, only when it is a short lowercase token, the server's `error.type` or `error.code`. Free-form server text is never copied, because servers echo prompts and key fragments. The key goes only into the `Authorization` header, never into a message, metadata, repr or persisted file. The run store's `secret_values` guard still applies on top.
11. **Hardened client.** `httpx` with `trust_env=False` (proxy variables, netrc and environment certificates are ignored), no redirects followed (so no header can be forwarded elsewhere), and TLS verification on for https. Plain http loads no CA bundle.
12. **Provenance.** Each result's `provider_metadata` carries `endpoint` (scheme, host, port and path, never credentials, query or fragment) and `api_style`. The manifest format is unchanged and does not record the endpoint, so provenance is per result, not per run.
13. **Dependency.** `httpx>=0.27,<1`. At the time of writing PyPI lists 0.27.0 to 0.28.1 with `requires_python >=3.8`; it depends on `anyio`, `certifi`, `httpcore` and `idna`. The standard library's `urllib` was rejected because it follows redirects and keeps the `Authorization` header on them.
14. **Boundary.** The core imports neither the adapter nor `httpx` (tests enforce it); the adapter imports the core but not the scorers.

## Limits
- Verified only against a local fake server that behaves as scripted. Real servers that call themselves OpenAI-compatible differ (for example in `seed`, `response_format` and the max-tokens field), and nothing here shows that any particular service works.
- `Retry-After` is read as seconds only; the HTTP-date form is ignored.
- The attempt history is written when a case finishes, so a crash during a retry loses it.
- Streaming, tool calls and several choices are not supported and fail closed. A run-level preflight of parameters does not exist: with an unsupported parameter every case is recorded as `unsupported_capability` without any HTTP request.
- The OpenAI four-sequence `stop` limit and parameter behaviour come from general knowledge of that API, not from this repository; they are profile settings so they can be corrected without code changes.
